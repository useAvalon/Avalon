---
title: Streaming SSR
description: How Avalon sends HTML to the browser today, when the streaming path applies, and what it does not do yet.
---

Avalon has two ways of sending a page: a buffered response and an experimental streaming response. Which one runs depends on whether your app uses layouts.

Avalon streams pages that use layouts. The layout head is sent first and `Suspense` content follows as it resolves. A page with nothing to wait for is sent as one complete document, exactly like a buffered response.

## How a layout response is sent

1. Avalon runs `getServerSideProps` and awaits the page component, including its islands. Errors here still produce a normal error response, because nothing has been sent yet.
2. The page markup is rendered with Preact's `renderToReadableStream` (from `preact-render-to-string/stream`). If it has no pending `Suspense` boundary, the whole document is sent in one piece.
3. If a `Suspense` boundary is still pending, Avalon sends the layout head and everything before the page (doctype, `<head>`, CSS, navigation) together with the page shell, where each boundary shows its `fallback`. Each boundary is then streamed when it resolves, and the layout's closing markup is sent last.

Island CSS and modulepreload links are collected while the page is awaited, so the flushed head is complete.

```tsx
import { Suspense } from 'preact/compat';

export default function Dashboard() {
  return (
    <main>
      <h1>Dashboard</h1>
      <Suspense fallback={<p>Loading stats…</p>}>
        <Stats />
      </Suspense>
    </main>
  );
}
```

Streamed responses carry `X-Accel-Buffering: no` so nginx-style proxies do not hold the body back. Avalon sets no other streaming header; a `Transfer-Encoding: chunked` header alone does not prove streaming, because proxies and CDNs add it. Check your CDN and compression settings: anything that buffers the whole body also removes the benefit.

## When Avalon buffers instead

Avalon sends a buffered response, with the same output, when:

- `streaming` is `false`.
- The app runs in development, uses the client router, or registers an HTML post-process hook (these need the whole document).
- The layout document cannot be split around the page, or the page contains a `<link>` stylesheet that the whole-document passes would inline.
- The app uses `core: "react"`. Streaming uses Preact's renderer.

Async page components are awaited before anything is sent, so slow data in the page component itself still delays the first byte. Wrap slow parts in `Suspense` to send the rest of the page first.

## If a streamed boundary fails

Once the head has been sent the status code cannot change. A boundary that throws is left to the client, as in Preact's streaming renderer. If rendering fails outright, Avalon logs the error, writes an error fragment and ends the document with the layout's closing tags.

## Turning streaming off

`streaming` is `true` by default. To always send complete documents:

```ts
// vite.config.ts
avalon({ nitro: { streaming: false } });
```

## Apps without layouts

Without layouts, the H3 handler has a separate fixed-shell streaming path. It sends a built-in document shell, awaits an async page and streams its rendered HTML inside `<div id="app">`. If the page component is not a function or its promise rejects, the response contains a client-rendered `<div id="app">` placeholder with `data-page` and `data-props` attributes.

## What this means for Core Web Vitals

Streaming lowers TTFB only for the parts of a page you put behind `Suspense`. Work done before the page component returns still happens before the first byte, so keep it fast: cache it, load it in parallel, or prerender the page.
